# Authentication

## Goal

Authentication verifies the identity of a user before allowing access to protected resources.

Authentication answers:

> Who are you?

Authorization answers:

> What are you allowed to do?

## UserRepository

Authentication reuses:

---

## Password Verification

Passwords are never compared directly.

Instead:

PasswordEncoder.matches(rawPassword, encodedPassword)

is used.

Why?

Passwords are stored as BCrypt hashes.

The original password cannot be recovered from the database.

When a user logs in, `PasswordEncoder.matches()` hashes the incoming raw password using BCrypt and compares it with the stored hash.

---

## InvalidCredentialsException

A single generic exception is thrown when:

- email does not exist
- password is incorrect

This avoids revealing whether an email exists in the system.

# JwtService

The JwtService is responsible for both generating and validating JWTs used for authentication.

Current implementation includes:

- Subject (email)
- Issued At (iat)
- Expiration Time (exp)
- HMAC SHA signing using a secret key
- The service is also responsible for parsing and validating incoming JWTs.

JWT Structure:

Header.Payload.Signature

The token is digitally signed so that it cannot be modified without the server's secret key.

The signing key and expiration time are configured through application.properties.

---

# JWT Validation

Generating a JWT is only the first half of authentication.

For every protected request, the server must:

- read the token
- verify its signature
- check its expiration
- identify the user
- place the authenticated user into Spring Security's context

JwtService now supports:

- extracting the subject (email)
- extracting the expiration time
- checking whether the token has expired
- validating that the token belongs to the expected user
- parsing and verifying signed JWT claims

Important methods:

```java
extractUsername(String token)
extractExpiration(String token)
isTokenExpired(String token)
isTokenValid(String token, String email)
```
JWT validation is performed using JJWT.

During validation the library automatically verifies:

- token signature
- token structure
- expiration time

If any verification fails, the request is treated as unauthenticated.

# JwtAuthenticationFilter

`JwtAuthenticationFilter` extends `OncePerRequestFilter`.

It executes once for every incoming HTTP request.

Responsibilities:

- Read the `Authorization` header.
- Check whether the header starts with `Bearer `.
- Extract the JWT.
- Extract the user's email.
- Load the user from the database.
- Validate the JWT.
- Create a UsernamePasswordAuthenticationToken object.
- Store the Authentication in `SecurityContextHolder`.
- Continue the filter chain.

Spring Security uses SecurityContextHolder to determine the currently authenticated user while processing the request. Controllers and other security components can access this authentication information without validating the JWT again.



Request Flow:

Client Request

↓

JwtAuthenticationFilter

↓

Extract JWT

↓

Validate JWT

↓

Load UserDetails

↓

Create Authentication

↓

SecurityContextHolder

↓

Spring Security Authorization Check

↓

Controller

# CustomUserDetailsService

Spring Security authenticates users through `CustomUserDetailsService`.

Responsibilities:

- Load users from MySQL.
- Find users using `UserRepository`.
- Throw `UsernameNotFoundException` if the user does not exist.
- Convert the application's `User` entity into Spring Security's `UserDetails`.

# Stateless Authentication

FocusGuard uses stateless authentication.

This means:

- no HTTP session is created
- every protected request must contain its JWT
- authentication is performed independently for every request

This is configured using:

```java
SessionCreationPolicy.STATELESS
```

---

# Security Configuration

The JWT filter is registered before Spring Security's UsernamePasswordAuthenticationFilter so that requests are authenticated using the JWT before Spring evaluates authorization rules.

This ensures JWT authentication is completed before authorization is checked.

Public endpoints:

- `/api/v1/health`
- `/api/v1/users/register`
- `/api/v1/auth/login`

All remaining endpoints require authentication.

# Authentication vs Authorization

Authentication

- Verifies identity.

Authorization

- Determines permissions after authentication succeeds.

Example:

Authentication

"Is this really Alice?"

Authorization

"Can Alice access the Admin dashboard?"

# Key Learnings

- Authentication verifies a user's identity.
- Authorization determines what an authenticated user is allowed to access.
- Separate authentication logic from user management logic.
- Passwords should always be stored as BCrypt hashes. 
- Never compare hashed passwords manually; use `PasswordEncoder.matches()`.
- JWTs are digitally signed, not encrypted.
- A JWT consists of a Header, Payload, and Signature.
- JWT payloads are readable by anyone, but only the server can generate a valid signature using its secret key.
- Never hardcode secret keys; store them in external configuration (and in production, use environment variables or a secrets manager).
- Keep authentication endpoints (e.g., `/api/v1/auth/login`) publicly accessible while protecting business endpoints.
- Return a consistent API response structure for easier client integration.
- JWT generation alone is not enough; every protected request must validate the token.
- `OncePerRequestFilter` guarantees that the JWT filter executes exactly once per request.
- `CustomUserDetailsService` allows Spring Security to authenticate users stored in the application's database.
- `SecurityContextHolder` stores the authenticated user for the lifetime of the current request.
- Stateless authentication removes the need for server-side HTTP sessions.
- Every protected API request must include a valid JWT.
- Invalid or modified JWTs are rejected before controller execution.
- Authentication establishes the user's identity before authorization determines whether the requested resource can be accessed.
